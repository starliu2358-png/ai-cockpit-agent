# 车书 AI V1.0 Design System

## Product context

车书 AI 是面向中国大陆 Tesla Model 3 用户的非官方车辆知识助手。它只做功能问答、手册检索、配置差异和边界识别，不控制车辆，也不读取实时车辆状态。首个里程碑以“如何打开充电口？”为真实端到端示例。

目标平台是桌面与移动端浏览器。桌面界面采用 HMI 风格的左右布局；移动端改为单列。产品应显得可靠、平静、现代和有生命力，而不是科幻控制台或传统后台管理系统。

## Visual direction

以清爽、简约的浅色信息型 HMI 为主。使用充足留白、白色卡片、轻量边框和克制阴影建立层级，避免玻璃拟态、厚重深色块、金色、紫色渐变、霓虹光晕、衬线字体或装饰性网络连线。

### Color tokens

- `--bg: #F6F8FA` — 页面背景
- `--surface: #FFFFFF` — 主卡片、侧栏和输入区
- `--surface-elevated: #EEF3F7` — 引用抽屉、悬浮层和选中区域
- `--text-primary: #17212B` — 主文字
- `--text-secondary: #667482` — 次要说明
- `--accent: #1677B8` — 发送、焦点、链接和当前选择
- `--accent-soft: rgba(22, 119, 184, 0.10)` — 轻量选中背景
- `--success: #178C5A` — 明确支持、成功和点赞
- `--danger: #D54848` — 明确不支持、错误和点踩
- `--warning: #B7791F` — 无法确认和需要注意
- `--border: #D9E1E8` — 默认边框
- `--border-strong: #B9C6D2` — 焦点与悬停边框

颜色不能单独承担语义；状态始终同时使用文字或图标。

## Typography

- 字体：系统无衬线字体栈，优先 `Inter`, `SF Pro Display`, `Segoe UI`, `PingFang SC`, `Microsoft YaHei`, sans-serif。
- 产品名：20–24px，700。
- 页面/回答标题：18–22px，650–700。
- 正文：15–16px，行高 1.65。
- 元数据与标签：12–13px，500–600。
- 不使用全大写长文本，不使用装饰性斜体。

## Layout

### Desktop

- 设计基准 1280×720，最小桌面内容宽度 960px。
- 顶栏高约 64px：左侧产品名，右侧安全提示与“非官方产品”。
- 主体为 280–320px 左侧栏 + 自适应对话区。
- 左侧栏包含 Model 3、配置选择、建议问题，以及“不控车、不读取实时状态”的边界说明。
- 对话区包含欢迎态、用户消息、AI 回答卡、引用和语音控制。
- 输入区固定在对话区底部，不覆盖内容。

### Mobile

- 以 390×844 为主要竖屏基准，同时支持横屏。
- 所有内容改为单列；车型和配置位于对话上方。
- 建议问题为可横向滚动的短 chips，但页面主体不得横向溢出。
- 输入区保持可见，软键盘弹出后仍能发送。
- 引用详情从右侧抽屉改为底部 sheet 或全宽覆盖层。

## Components

- Header：简洁，无品牌 Logo 占位；左侧显示“车书 AI”，右侧只显示“非官方产品”，不显示其他提示文案。
- Vehicle selector：Tesla Model 3 固定文本 + 四配置下拉框，不显示地区或软件版本。
- Suggestion chips：短句、轻边框、单击直接填入或提交问题。
- Conversation：用户消息靠右但不过度气泡化；AI 回答占主宽度。
- Answer card：先给直接结论，再显示步骤；底部排列引用、播放/暂停、点赞、点踩。
- Citation panel/sheet：显示来源标题、章节、官方域名、核验日期和打开原文按钮。桌面端打开后作为右侧固定宽度栏参与布局，对话区同步收窄，绝不覆盖回答正文；移动端使用底部 sheet 覆盖。
- Composer：多行输入、麦克风按钮、发送按钮；麦克风为“尚未接通语音识别”的可恢复状态。
- Feedback：点赞/点踩互斥，可切换；选中有颜色、图标和辅助文本反馈。
- Loading：使用轻量脉冲和“正在查找官方资料”，避免长流程动画。
- Unconfirmed/error：清楚解释资料不足或服务失败，提供重试，不使用“功能不支持”代替零检索。

## Motion and interaction

- 动画 140–220ms，使用 `cubic-bezier(0.4, 0, 0.2, 1)`。
- 卡片只使用非常轻的透明度、位移和边框变化；禁止大幅缩放和持续发光。
- 所有触控目标至少 44×44px。
- 桌面键盘焦点清楚可见；移动端不依赖 hover。

## Required draft states

同一设计草案必须展示或明确覆盖：

1. 初始欢迎态与建议问题。
2. “如何打开充电口？”成功回答，包含步骤、官方引用、TTS、点赞/点踩。
3. 正在加载官方资料。
4. 资料不足/无法确认。
5. API 失败并可重试。
6. 桌面端不遮挡正文的并排引用栏，以及移动端底部 sheet。
7. 麦克风不可用但文字输入正常。
8. 桌面左右布局与移动端单列布局。

## Content constraints

- 语气自然、直接、简短，避免机械地展示市场代码或软件版本。
- 普通操作问答不展示三态标签。
- 右上角只显示“非官方产品”，不显示“界面草稿”或“仅供参考，请以官方手册为准”。
- 不出现车速、电量、空调、车门控制等实时车辆控件。
- 不仿冒 Tesla 官方视觉或使用 Tesla 商标作为产品 Logo。
